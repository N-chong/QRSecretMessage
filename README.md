# QRSecure

QRSecure is an offline Ionic/Angular Android application for creating password-protected encrypted QR messages. A sender encrypts plaintext with a message-specific password and shares the QR image; a receiver scans or uploads the image and enters that same password. The password is never included in the QR.

The application lock is deliberately separate: a 4- or 6-digit QRSecure PIN (and optional device biometrics) protects access to the app and its encrypted history. It is never used to encrypt messages.

## Security design

- AES-256-GCM authenticated encryption through Web Crypto
- PBKDF2-SHA-256 with 310,000 iterations and a fresh 128-bit salt per message
- Fresh 96-bit IV per message
- App PIN stored only as a salted PBKDF2 verifier in Android secure storage
- Local JSON history contains ciphertext, salt, IV, dates, title, and status only
- No plaintext messages, message passwords, PINs, AES keys, or decrypted history are stored
- Native biometric authentication with PIN fallback and escalating PIN retry delays
- Local expiration and one-time-open checks

One-time mode is enforced only on each local device. A QR image can be copied, so true global one-time enforcement is impossible without a server. QRSecure intentionally has no server or cloud database.

## Install and browser test

Requirements: Node.js `22.22.3` or another version accepted by the installed Angular release, and npm.

```bash
npm ci
npm start
```

Open `http://localhost:4200`. Browser testing supports PIN setup, encryption, QR generation, uploaded-image decoding, decryption, history, and themes. Native secure storage and fingerprint prompts are represented by plugin web implementations; verify the real security flow on Android hardware. Camera scanning in a browser depends on Barcode Detector support, so gallery upload is the most reliable browser test.

Run automated tests and the production build:

```bash
npm test -- --configuration=ci
npm run build
```

## Android setup and permissions

The `android/` project is committed. If recreating it from a web-only checkout:

```bash
npm run build
npx cap add android
npx cap sync android
```

`android/app/src/main/AndroidManifest.xml` declares camera and biometric permissions, marks the camera optional, and registers the Google ML Kit barcode UI module. Android 7.0/API 24 is the minimum generated by Capacitor 8.

After any web or plugin change, run:

```bash
npm run build
npx cap sync android
```

## Real-device fingerprint and camera testing

1. Enroll a fingerprint and configure a secure device lock in Android Settings.
2. Install and open the APK, create a QRSecure PIN, and enable fingerprint during setup or in Settings.
3. Background and resume the app to verify the selected auto-lock timeout.
4. Choose **Use PIN Instead** to verify fallback behavior.
5. For camera tests, grant camera permission when prompted, scan a QRSecure QR displayed on a second device, and test low light/flash controls offered by the native scanner.
6. Save or screenshot a generated QR and test **Upload QR** from the gallery.
7. Verify that a wrong message password shows only the generic error and that the correct sender-created password reveals the plaintext.

Biometric enrollment and the native camera cannot be fully validated in a desktop browser or most emulators; use a physical Android phone for final acceptance.

## Build an APK locally

Install Android Studio/Android SDK and JDK 21, then run:

```bash
npm ci
npm run build
npx cap sync android
cd android
./gradlew assembleDebug
```

On Windows PowerShell use `.\gradlew.bat assembleDebug`. The APK is written to `android/app/build/outputs/apk/debug/app-debug.apk`.

## Build and download the APK with GitHub Actions

Push the repository to GitHub with the default branch named `main`, or open **Actions → Build Android APK → Run workflow** for a manual build. The workflow installs locked npm dependencies, runs tests, builds the web application, syncs Capacitor, builds with JDK 21, and fails visibly on any test/build error.

After a successful run:

1. Open the GitHub repository.
2. Select **Actions**.
3. Open the successful **Build Android APK** run.
4. Under **Artifacts**, download **qrsecure-debug-apk**.

This is an unsigned debug build intended for development and demonstrations. A release workflow can later use GitHub encrypted secrets for a keystore; never commit signing keys or passwords.

## Troubleshooting CI builds

- **`npm ci` fails:** commit the current `package-lock.json` and do not edit it manually.
- **Unsupported Node engine:** keep the workflow Node version aligned with `@angular/core`'s engine requirement.
- **Java/Gradle failure:** Capacitor 8 compiles Java 21 here; keep Temurin 21 and the committed Gradle wrapper.
- **Capacitor plugin missing:** run `npm install`, `npm run build`, and `npx cap sync android`, then commit dependency and native project changes.
- **APK artifact missing:** read the Gradle step error first; the upload step intentionally uses `if-no-files-found: error`.
- **Camera does not open:** verify permission in Android Settings and confirm Google Play Services/ML Kit is available on the device.
- **Fingerprint unavailable:** enroll biometrics and enable a secure device screen lock before enabling the toggle.

## Project layout

Feature pages are under `src/app/pages`; authentication, encryption, QR, validation, storage, sharing, and biometrics are separate services under `src/app/services`. Models and binary/password utilities live in their own folders. The APK workflow is exactly at `.github/workflows/build-apk.yml`.
